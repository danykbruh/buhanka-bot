# Буханка - Telegram Mini App + бот

Концепт заказа с самовывозом для пекарни "Буханка". **Не является официальным сервисом пекарни.**

```
webapp/            статичный мини-апп (выкладывается на GitHub Pages)
  index.html
  style.css
  app.js           логика: каталог, поиск, товар, корзина, оформление
  menu.json        меню, цены, лимиты, часы. Общий файл для мини-аппа и бота (TODO: сверить)
  bakeries.js      пекарни для самовывоза (с карты сети, данные на 20.10.2026), его тоже читает бот
  promo-codes.json правила промокодов для предпросмотра скидки (генерируется, руками не править)
  img/menu/*.webp  фото 4:3, имя файла = id позиции
bot/               бот на Python + aiogram 3
  bot.py           хендлеры, логи, запуск
  order.py         проверка заказа: пересчёт по menu.json, пекарня, слот
  storage.py       SQLite: заказы, статусы, номера, антиспам, штампы, счётчики
  promos.json      промокоды: источник правды для скидок
  export_promos.py выгружает хеши промокодов в webapp/promo-codes.json
  tests/           pytest: пересчёт скидок и бонусов
  Dockerfile, docker-compose.yml
  requirements.txt
  .env.example
.github/workflows/pages.yml   автодеплой webapp/ на Pages
```

Как это работает: гость пишет боту `/start` и нажимает кнопку **"Открыть меню"** под полем ввода. Мини-апп собирает заказ и отправляет его боту через `Telegram.WebApp.sendData`. Бот пересчитывает заказ по своему меню, присылает гостю чек и дублирует заказ админу.

> **Важно.** Telegram передаёт `sendData` только если мини-апп открыт **кнопкой клавиатуры** (KeyboardButton), которую выдаёт бот по `/start`. Из кнопки меню бота, из профиля или по прямой ссылке заказ не отправится, мини-апп в этом случае покажет подсказку.

## 1. Создать бота

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте имя и username. Сохраните токен.
2. Узнайте свой числовой id, например через [@userinfobot](https://t.me/userinfobot), это будет `ADMIN_CHAT_ID`. Для группы: добавьте бота в группу, id группы начинается с `-100`.

## 2. Выложить webapp на GitHub Pages

1. Создайте репозиторий на GitHub и запушьте весь проект в ветку `main`:
   ```bash
   git init
   git add .
   git commit -m "Буханка: мини-апп и бот"
   git branch -M main
   git remote add origin https://github.com/<логин>/<репозиторий>.git
   git push -u origin main
   ```
   Файл `.env` в `.gitignore`, токен в репозиторий не попадёт.
2. В репозитории: **Settings -> Pages -> Build and deployment -> Source: GitHub Actions**.
3. Workflow `Deploy webapp to Pages` сам запустится при пуше (или запустите вручную во вкладке **Actions**). Через минуту мини-апп будет доступен по адресу
   `https://<логин>.github.io/<репозиторий>/`.
   Это и есть `WEBAPP_URL`. Проверьте, что он открывается в браузере.

Без Actions: можно переложить содержимое `webapp/` в корень отдельного репозитория и выбрать **Source: Deploy from a branch -> main / root**.

## 3. Запустить бота на своём компьютере

Нужен Python 3.10+. Для постоянной работы лучше сервер, см. раздел "Деплой на VPS".

```bash
cd bot
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env        # Windows: copy .env.example .env
```

Заполните `bot/.env`:

```
BOT_TOKEN=123456:ABC...
ADMIN_CHAT_ID=123456789
WEBAPP_URL=https://<логин>.github.io/<репозиторий>/
```

Запуск:

```bash
python bot.py
```

Бот читает меню и пекарни из `webapp/menu.json` и `webapp/bakeries.js`, поэтому запускайте его из полной копии репозитория (или задайте пути в `MENU_FILE` и `BAKERIES_FILE`). Логи пишутся в `bot/logs/`, база заказов - в `bot/data/orders.db`.

Проверка: напишите боту `/start`, нажмите **"Открыть меню"**, соберите заказ, нажмите **"Отправить заказ"**. В чат придёт чек, админу - копия заказа. Админ может отправить `/health`.

## 4. Привязать мини-апп к боту в @BotFather

Для работы заказов достаточно шагов выше: кнопку с мини-аппом выдаёт сам бот по `/start`, отдельная регистрация в BotFather для неё не нужна. Что ещё стоит настроить в @BotFather (`/mybots` -> ваш бот):

- **Edit Bot -> Edit Botpic** - аватар.
- **Команды, описание и кнопку меню ставит сам бот при запуске**, руками в @BotFather их настраивать не нужно: команды `/start` (Открыть меню), `/orders` (Мои заказы), `/bonus` (Мои штампы), короткое описание и описание с пометкой "Концепт, не официальный бот пекарни Буханка", а слева от поля ввода - список команд (`set_chat_menu_button` типа commands). `/health` в список не входит, она только для админа. Если поменяете тексты в @BotFather, бот перезапишет их при следующем запуске; сами тексты - в начале `bot/bot.py`.
- **Bot Settings -> Configure Mini App -> Enable Mini App**, URL = `WEBAPP_URL`. Появится кнопка "Open" в профиле бота и прямая ссылка `t.me/<бот>?startapp`. Это удобно для витрины, но **заказы оттуда не отправляются** (ограничение `sendData`), мини-апп попросит открыть его через кнопку в чате.
- **Bot Settings -> Menu Button** не меняйте на мини-апп: бот сам ставит туда список команд, потому что из кнопки меню заказ не уйдёт.

**Приветствие на `/start`:** обложка `webapp/img/cover.png` (1280x720) с подписью "как заказать" и inline-кнопками "Мои заказы" и "Мои штампы", следом короткое сообщение, которое ставит нижнюю кнопку **"Открыть меню"**. Это два сообщения, потому что у одного сообщения может быть только одна клавиатура: либо inline-кнопки, либо нижняя. Кнопки мини-аппа среди inline нет намеренно: заказ через `sendData` доходит только из нижней кнопки. Обложку бот загружает один раз, дальше отправляет по `file_id`; если файла нет, приветствие уходит текстом.

Чтобы принимать заказы из меню-кнопки и прямых ссылок, нужен бэкенд с `answerWebAppQuery` и проверкой `initData`, это следующий шаг развития проекта.

## Деплой на VPS

Подойдёт любой VPS с Ubuntu 22.04 или 24.04 и 1 ГБ памяти. Белый IP, домен и открытые порты не нужны: бот сам ходит в Telegram (long polling). Мини-апп по-прежнему живёт на GitHub Pages.

**1. Установите Docker** (официальный скрипт, ставит Docker и плагин compose):

```bash
sudo apt update && sudo apt install -y git curl
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER   # чтобы не писать sudo перед docker
```

Выйдите из SSH и зайдите снова, чтобы применилась группа. Проверка: `docker compose version`.

**2. Склонируйте репозиторий:**

```bash
git clone https://github.com/<логин>/<репозиторий>.git buhanka-bot
cd buhanka-bot/bot
```

**3. Создайте `.env`** (токен только здесь, в git его нет):

```bash
cp .env.example .env
nano .env        # впишите BOT_TOKEN, ADMIN_CHAT_ID, WEBAPP_URL; сохранить: Ctrl+O, Enter, Ctrl+X
chmod 600 .env
```

**4. Создайте папки для логов и базы.** Бот в контейнере работает не от root (uid 1000), поэтому папки должны принадлежать этому пользователю:

```bash
mkdir -p logs data
sudo chown 1000:1000 logs data
```

**5. Запустите:**

```bash
docker compose up -d --build
docker compose ps            # статус должен быть Up
docker compose logs -f       # живые логи, выход: Ctrl+C
```

Напишите боту `/start` и сделайте тестовый заказ, затем отправьте `/health` из админского аккаунта.

**Что дальше:**

- **Автозапуск.** `restart: unless-stopped` поднимает бота после падения и после перезагрузки сервера (Docker сам стартует при загрузке). Остановить: `docker compose down`.
- **Логи.** Файлы в `bot/logs/`: `bot.log` и до 4 старых по 1 МБ. Последние строки: `tail -n 100 logs/bot.log`.
- **Обновление** (новый код, меню или пекарни):
  ```bash
  cd ~/buhanka-bot && git pull && cd bot && docker compose up -d --build
  ```
  Меню и пекарни копируются в образ при сборке. Если поменяли `webapp/menu.json`, обновите и бота: иначе он будет считать заказы по старым ценам и отвечать гостям "Меню обновилось".
- **Смена токена или настроек:** поправьте `.env` и выполните `docker compose up -d` (контейнер пересоздастся).
- **Бэкап.** Вся история заказов и нумерация - в `bot/data/orders.db`. Скопировать к себе: `scp <сервер>:~/buhanka-bot/bot/data/orders.db .`

## Статусы заказов

Копия заказа приходит в `ADMIN_CHAT_ID` с кнопками **Принят**, **Готовится**, **Готов к выдаче**, **Отменён**. По нажатию бот:

- перерисовывает сообщение у админа: внизу текущий статус и время, нажатая кнопка отмечена точкой;
- пишет гостю: "Заказ №1001 принят. Ждём вас сегодня, 12:30: <адрес>", "Заказ №1001 готов, ждём вас: <адрес>" и т.д. Если гость заблокировал бота, статус всё равно сохраняется, а админ видит предупреждение.

Нажимать кнопки может только `ADMIN_CHAT_ID`: сам этот пользователь или любой участник этой группы. Остальным бот отвечает отказом.

Гость видит свои последние 5 заказов со статусами по команде `/orders`. Заказы и статусы хранятся в `bot/data/orders.db` и переживают перезапуск; при обновлении бота старая база дополняется новыми колонками без потери заказов.

## Акции и бонусы

**Баннеры.** Карусель вверху мини-аппа берётся из `promos` в `webapp/menu.json`:

- `title` (Oswald 19px, не больше 2 строк) и `subtitle` (1-2 строки). Рядом с фото на экране 375px тексту остаётся 128px: проверяйте, что заголовок помещается в 2 строки, длинное слово вроде "бесплатно" занимает почти всю строку;
- `image` - фото справа, например `img/menu/latte.webp`. Оно стоит в рамке 4:3 во всю высоту баннера и показывается целиком, поэтому фото тоже должно быть 4:3. Коллажи комбо сюда не подходят: в маленькой рамке они нечитаемы;
- необязательно `hours: ["00:00", "10:00"]` - показывать только в это время пекарни;
- `action` - что делает нажатие на баннер: `{"type": "code", "code": "KOFE"}` применяет промокод, `{"type": "tab", "cat": "combo"}` переключает на вкладку каталога, `{"type": "item", "id": "combo-2"}` открывает товар, `{"type": "info", "title": "...", "lines": ["..."]}` показывает окно с правилами.

Баннер 140px в высоту: слева текст на сплошном фоне, справа фото 187x140. Слайд на всю ширину экрана минус поля, соседний не выглядывает, позицию показывают точки. Автопрокрутка раз в 5 секунд, пауза после касания. На экранах уже 360px баннер 112px (фото 149x112), иначе тексту остаётся 79px.

## Обновление мини-аппа и кэш Telegram

Telegram подолгу держит в кэше `style.css` и `app.js`. Поэтому в `index.html` к ним (и к `bakeries.js`) добавлена версия: `style.css?v=20261027-2`. **При каждом выпуске меняйте её во всех трёх ссылках** (дата и номер выпуска за день), иначе часть гостей увидит старую вёрстку. `menu.json` и `promo-codes.json` мини-апп загружает с `cache: "no-cache"`, им версия не нужна.

**Промокоды** хранятся у бота в `bot/promos.json`: `percent`, `scope` (`all` - весь заказ, `coffee` - только кофе), `valid_from`/`valid_to` (включительно, по времени пекарни), необязательно `before` - код действует только при заказе до этого времени. Тестовые коды: `BUHANKA10` (-10% на весь заказ) и `KOFE` (-20% на кофе при заказе до 10:00).

- Мини-апп показывает скидку заранее по `webapp/promo-codes.json`. Там нет самих кодов, только SHA-256 и правила. Это прячет список от случайного взгляда, но короткий код можно подобрать перебором, поэтому секретом файл не считается.
- **Итог считает только бот.** Он заново проверяет код и пересчитывает скидку. Неизвестный, ещё не начавшийся или истёкший код, KOFE после 10:00 или без кофе в заказе - гость получает понятное сообщение, заказ не принимается. Если скидка у бота разошлась с показанной, заказ принимается по сумме бота, и в чеке есть пояснение.
- **После правки `bot/promos.json`** выполните `python bot/export_promos.py`, запушьте `webapp/promo-codes.json` и перезапустите бота. Тест `test_promo_export_is_up_to_date` упадёт, если забыть выгрузку.
- Скидка в процентах округляется вниз до рубля и считается от цен меню.

**Каждый 6-й кофе в подарок.** Кофе - позиции с `"coffee": true` в `menu.json` (американо, капучино, латте, раф). Чай и кофе в комбо не считаются: комбо и так со скидкой.

- Штампы бот считает по заказам гостя в SQLite, только со статусом **"Готов к выдаче"**. Если админ потом сменит статус, штампы пересчитаются.
- Когда набралось 5, бот сам делает бесплатным самый дорогой кофе в следующем заказе и пишет об этом в чеке. Подарок списывается сразу при оформлении, а если этот заказ отменят, возвращается.
- Вместе с промокодом: скидка по коду считается как обычно, а подарок обнуляет остаток цены этой чашки, так что она стоит ровно 0 ₽.
- Гость видит прогресс командой `/bonus` (🟤🟤🟤⚪⚪ "У вас 3 из 5 штампов"), а при статусе "Готов к выдаче" бот сразу пишет, сколько штампов добавилось. В корзине мини-аппа строка "Бонусы проверит бот при оформлении".

**Тесты** на пересчёт скидок и бонусов:

```bash
pip install -r bot/requirements-dev.txt
pytest bot/tests
```

## Поиск

Отдельный экран (вкладка "Поиск" или поле на главной). Ищет без учёта регистра и буквы ё по названию, составу и тегам: своим тегам позиции (`tags` в `menu.json`: "сладкое", "сытное", "для детей"), подгруппе и категории. Окончания отбрасываются ("пончики" находит пончик), синонимы - в `searchSynonyms` (`"кофе": ["американо", "латте", ...]`). Совпадения в названии выделены жирным.

- До ввода: "Недавние запросы" (до 5, в CloudStorage с копией в localStorage, с очисткой) и чипсы "Популярное".
- Фильтры: "Без глютена" (для комбо учитываются все возможные составляющие), "До 200 ₽", "Сладкое", "Сытное", "Напитки"; работают и без запроса.
- Ничего не нашлось - "Ничего не нашли" и 4 позиции из `popular`.

## Мои заказы и избранное в мини-аппе

- **Навигация.** Внизу панель "Меню", "Поиск", "Заказы", "Корзина" (с бейджем количества). Поиск и заказы сменяют друг друга, а не копятся. На экране товара вместо панели своя закреплённая кнопка "Добавить", в корзине и оформлении - Telegram MainButton ("Оформить", "Отправить заказ"); в остальных местах MainButton скрыт, чтобы не перекрывать панель. Telegram BackButton появляется на товаре, в поиске, заказах, корзине и оформлении. Переходы 200 мс, прокрутка каталога сохраняется при возврате с экрана товара.

- **Мои заказы** (иконка чека в шапке): последние 10 заказов - номер и дата, статус бейджем, миниатюры позиций (до 4 и "+N"), пекарня, сумма и кнопка **Повторить**, которая кладёт те же позиции с теми же опциями в корзину. Если позиции уже нет в меню или изменились её опции, она пропускается, а мини-апп показывает, что именно не добавилось. Пустой экран предлагает перейти в меню и показывает ленту популярных позиций (`popular` в `menu.json`).
- **Номера, статусы и штампы** знает только бот, а мини-апп статичный и спросить его не может. Поэтому бот передаёт их в адресе кнопки "Открыть меню": `?st=3&gift=0&o=1012.c.1761549300.1060,...` (штампы, доступные подарки, затем по последним 5 заказам номер, статус `n/a/c/r/x`, время оформления и сумма). Кнопку бот обновляет в каждом своём сообщении: в чеке, при смене статуса, по `/start`, `/orders`, `/bonus`. Мини-апп сопоставляет заказ из своей истории с заказом бота по времени отправки (до 3 минут разницы). Данные только для показа: скидки и проверки считает бот. Если гость открыл мини-апп старой кнопкой, статусы будут на момент последнего сообщения бота.
- **Избранное:** сердечко на карточке и на фото товара. Вкладка "Избранное" появляется первой среди категорий, только когда в избранном что-то есть.
- Всё это, как и выбранная пекарня, хранится в `Telegram.WebApp.CloudStorage` и поэтому видно на всех устройствах гостя. Копия всегда лежит в `localStorage`: это запасной вариант для старых клиентов Telegram и браузера. В облаке одно значение ограничено 4096 символами, поэтому туда уходят самые свежие заказы, которые помещаются, а локально хранятся все 10.

## Надёжность бота

- **Заказ проверяет `validate_order` в `bot/order.py`.** От мини-аппа бот берёт только id позиций, количество, опции (в том числе состав комбо), промокод, пекарню, время самовывоза, имя и комментарий. Цены, суммы и скидку бот считает сам: по `menu.json`, `bot/promos.json` и штампам из своей базы.
- **Цены или сумма из мини-аппа не совпали** (меню обновилось, пока корзина была открыта, или данные подменили): заказ принимается по сумме бота. В чеке гость видит пояснение "Цены в корзине отличались от актуального меню... К оплате: N ₽", в лог пишется строка `Сумма не совпала: user_id=... expected=... sent=...`.
- **Неверные данные** (неизвестный id или опция, количество вне 1-20, истёкший или неподходящий промокод, время в прошлом или вне часов работы, сообщение больше 4096 байт) - заказ не принимается, гость получает вежливое сообщение без технических подробностей, причина пишется в лог.
- **Подпись initData.** Если мини-апп приложил `initData`, бот проверяет её HMAC по [документации Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), срок (24 часа) и что id гостя совпадает с отправителем. При запуске с кнопки клавиатуры (`sendData`) Telegram initData не передаёт, тогда проверка пропускается.
- **Лимиты** (в `menu.json`, раздел `limits`, их же соблюдает мини-апп): одной позиции от 1 до 20 штук, в заказе не больше 30 позиций, имя до 50 символов, комментарий до 300. Пекарня только из списка. Время самовывоза только из слотов, которые мини-апп мог показать (шаг 15 минут, часы работы, сегодня или завтра), и не в прошлом. Слоты считаются по московскому времени и в мини-аппе, и в боте, поэтому часовой пояс телефона и сервера не важен.
- **Антиспам:** не больше 3 заказов за 10 минут от одного гостя, иначе вежливый отказ. Одинаковый заказ, пришедший повторно в течение 30 секунд, считается двойным нажатием и игнорируется.
- **Ошибки** в обработчиках пишутся в лог и не роняют бота. Гость получает "Что-то пошло не так", админ - короткое сообщение об ошибке, не чаще раза в 5 минут (пропущенные считаются и попадают в следующее).
- **Номера заказов** хранятся в SQLite (`bot/data/orders.db`), начинаются с 1001 и продолжаются после перезапуска.
- **`/health`** отвечает только в чате `ADMIN_CHAT_ID` (или пользователю с этим id): аптайм, заказы и выручка за сегодня, последний номер, версия меню, число пекарен и ошибок с запуска. Остальным бот отвечает как на обычное сообщение.
- Весь текст гостя в сообщениях бота экранируется (HTML).

## Меню и цены

Всё меню - в `webapp/menu.json`. Это обычный JSON: комментариев нет, пояснения лежат в полях `_about` и `_todo`. **Цены, вес, калорийность и состав примерные, перед запуском сверьте их.** После правки меню запушьте его (обновится мини-апп) и обновите бота на сервере.

- `version` - версия меню, видна в `/health` и уходит в заказе.
- `timezone.utcOffsetMinutes` - часовой пояс пекарен (180 = Москва), по нему считаются слоты.
- `limits` - лимиты заказа, см. "Надёжность бота".
- `bakery` - общие часы работы, время на сборку заказа (`prepMinutes`), шаг и число слотов.
- `categories` - вкладки каталога. На экране только позиции активной вкладки; переключение плавное, свайпом влево и вправо по списку можно перейти на соседнюю, последняя вкладка запоминается. `groups` у категории - подгруппы с маленькими заголовками внутри вкладки (`{"title": "Круассаны", "items": [id, ...]}`); позиции без подгруппы попадают в конец, в "Ещё". Вкладка "Комбо" показывает крупные карточки по одной в ряд с составом и выгодой (выгода считается по `parts`). Поиск ищет по всем категориям и на это время скрывает вкладки.
- `popular` - позиции для ленты "Попробуйте" на пустом экране "Мои заказы".

Поля позиции в `items`:

| Поле | Что это |
|---|---|
| `id` | совпадает с именем фото `img/menu/<id>.webp` |
| `cat` | id категории из `categories` |
| `title`, `desc` | название и описание для экрана товара |
| `composition` | состав простыми словами |
| `weight`, `kcal` | вес в граммах (выпечка) или объём в мл (напитки) и калорийность; у напитков с выбором объёма - для 300 мл, для 400 мл пересчитывается |
| `allergens` | из списка `allergens` |
| `pairing` | id 1-2 позиций для ленты "С этим берут" |
| `short` | строка на карточке в сетке, если её нельзя собрать из веса |
| `price` | базовая цена, ₽ |
| `badge` | плашка на фото ("Хит") |
| `imgPos` | своё кадрирование фото (`object-position`), если еда не по центру. По умолчанию `center 70%` |
| `options` | группы опций: `required`, `default`, варианты с доплатой `delta`. Если у обязательной группы нет `default`, "+" на карточке открывает экран товара |
| `parts` | у комбо: из чего состоит набор. `{ "id" }` - позиция меню, `{ "group" }` - позиция, выбранная в группе опций. `price`, `kcal`, `note` переопределяют значения, если в комбо порция другая. По `parts` считаются экономия, калорийность и аллергены |

Фото: `webapp/img/menu/<id>.webp`, 4:3.

Цвета и шрифты - фирменный стиль сайта buhanka.ru (только цвета, без логотипа и картинок сайта). Палитра задана CSS-переменными в начале `style.css`, светлая и тёмная. Тёмной темы на сайте нет, она подобрана в той же гамме и включается по теме Telegram или системы. Цвета шапки, фона и MainButton Telegram мини-апп берёт из тех же переменных.

| Роль | Светлая | Тёмная |
|---|---|---|
| фон | `#FFFFFF` | `#1A1A1A` |
| карточки, текстовая часть баннеров | `#FCF7ED` | `#242424` |
| текст, цены, ссылки | `#242424` | `#F5F2EA` |

| акцент: заливка кнопок, активной вкладки, бейджа, MainButton, точек карусели | `#FED36B`, текст на нём `#242424` (10.8:1) | так же |

Жёлтый - только заливка: жёлтый текст на белом даёт 1.4:1, поэтому цены и ссылки тёмные, цены выделены жирностью 700. Шрифты из Google Fonts: Inter для текста, Oswald для заголовков (название в шапке и заголовки разделов капслоком, как на сайте; названия товаров обычным регистром).

## Пекарни для самовывоза

Список - в `webapp/bakeries.js`: 233 точки с карты пекарен на сайте сети https://buhanka.ru/map/, выгрузка 20.10.2026. Источник и что сделано с данными описаны в шапке файла. **Адреса нужно периодически сверять с картой сети.**

- Метро и часов работы в источнике нет. Если добавить точке `metro`, по нему заработает поиск; если добавить `hours: "08:00-21:00"`, слоты самовывоза для неё будут строиться по этим часам (и в мини-аппе, и при проверке в боте).
- Тот же файл читает бот: он проверяет, что `id` пекарни из заказа есть в списке, и берёт адрес из списка, а не из присланных данных. Поэтому после правки списка обновите бота.
- "Ближайшая ко мне" использует `Telegram.WebApp.LocationManager` (Telegram 8.0+), в старых клиентах и в браузере - `navigator.geolocation`. Геолокация работает только по https или на `localhost`.

## Локальная проверка мини-аппа

Меню загружается из `menu.json`, поэтому двойной клик по `index.html` не сработает (браузер не даёт читать файлы с `file://`). Запустите локальный сервер:

```bash
cd webapp
python -m http.server 8000
```

и откройте http://localhost:8000. Вне Telegram вместо системных кнопок появляется своя кнопка внизу, а "отправка" заказа печатает JSON в консоль браузера.

## Безопасность и ограничения концепта

- Токен и id админа только в переменных окружения, в коде и в Docker-образе их нет.
- Бот не доверяет данным из мини-аппа: пересчитывает цены, проверяет лимиты, пекарню и слот, экранирует текст. Битые данные не роняют бота: гость получает понятный ответ, в лог пишется причина.
- Оплата не подключена: "оплата при получении".
