# Буханка - Telegram Mini App + бот

Концепт заказа с самовывозом для пекарни "Буханка". **Не является официальным сервисом пекарни.**

```
webapp/            статичный мини-апп (выкладывается на GitHub Pages)
  index.html
  style.css
  app.js           логика: каталог, поиск, товар, корзина, оформление
  menu.js          данные меню и цены (TODO: сверить цены)
  img/menu/*.webp  фото 4:3, имя файла = id позиции
bot/               бот на Python + aiogram 3
  bot.py
  requirements.txt
  .env.example
.github/workflows/pages.yml   автодеплой webapp/ на Pages
```

Как это работает: гость пишет боту `/start` и нажимает кнопку **"🥐 Открыть меню"** под полем ввода. Мини-апп собирает заказ и отправляет его боту через `Telegram.WebApp.sendData`. Бот присылает гостю чек и дублирует заказ админу.

> **Важно.** Telegram передаёт `sendData` только если мини-апп открыт **кнопкой клавиатуры** (KeyboardButton), которую выдаёт бот по `/start`. Из кнопки меню бота, из профиля или по прямой ссылке заказ не отправится, мини-апп в этом случае покажет подсказку.

## 1. Создать бота

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте имя и username. Сохраните токен.
2. Узнайте свой числовой id, например через [@userinfobot](https://t.me/userinfobot), это будет `ADMIN_CHAT_ID`. Для группы: добавьте бота в группу, id группы начинается с `-100`.

## 2. Выложить webapp на GitHub Pages

1. Создайте репозиторий на GitHub и запушьте весь проект в ветку `main`:
   ```bash
   git init
   git add .
   git commit -m "Буханка: мини-апп и бот"
   git branch -M main
   git remote add origin https://github.com/<логин>/<репозиторий>.git
   git push -u origin main
   ```
   Файл `.env` в `.gitignore`, токен в репозиторий не попадёт.
2. В репозитории: **Settings -> Pages -> Build and deployment -> Source: GitHub Actions**.
3. Workflow `Deploy webapp to Pages` сам запустится при пуше (или запустите вручную во вкладке **Actions**). Через минуту мини-апп будет доступен по адресу
   `https://<логин>.github.io/<репозиторий>/`.
   Это и есть `WEBAPP_URL`. Проверьте, что он открывается в браузере.

Без Actions: можно переложить содержимое `webapp/` в корень отдельного репозитория и выбрать **Source: Deploy from a branch -> main / root**.

## 3. Запустить бота

Нужен Python 3.10+.

```bash
cd bot
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env        # Windows: copy .env.example .env
```

Заполните `bot/.env`:

```
BOT_TOKEN=123456:ABC...
ADMIN_CHAT_ID=123456789
WEBAPP_URL=https://<логин>.github.io/<репозиторий>/
```

Запуск:

```bash
python bot.py
```

Переменные можно задать и обычным окружением (на сервере, в Docker), `.env` тогда не нужен. Бот работает через long polling, вебхук и белый IP не нужны. Чтобы бот работал постоянно, запустите его на сервере/VPS (systemd, Docker, screen) - на компьютере он работает, пока открыт терминал.

Проверка: напишите боту `/start`, нажмите **"🥐 Открыть меню"**, соберите заказ, нажмите **"Отправить заказ"**. В чат придёт чек, админу - копия заказа.

## 4. Привязать мини-апп к боту в @BotFather

Для работы заказов достаточно шагов выше: кнопку с мини-аппом выдаёт сам бот по `/start`, отдельная регистрация в BotFather для неё не нужна. Что ещё стоит настроить в @BotFather (`/mybots` -> ваш бот):

- **Edit Bot -> Edit Description / About / Botpic** - описание и аватар. В описании упомяните, что это концепт.
- **Edit Bot -> Edit Commands** (или `/setcommands`): `start - Открыть меню`.
- **Bot Settings -> Configure Mini App -> Enable Mini App**, URL = `WEBAPP_URL`. Появится кнопка "Open" в профиле бота и прямая ссылка `t.me/<бот>?startapp`. Это удобно для витрины, но **заказы оттуда не отправляются** (ограничение `sendData`), мини-апп попросит открыть его через кнопку в чате.
- **Bot Settings -> Menu Button** - лучше оставить стандартное меню команд. Если поставить туда мини-апп, гости будут открывать его кнопкой, из которой заказ не уйдёт.

Чтобы принимать заказы из меню-кнопки и прямых ссылок, нужен бэкенд с `answerWebAppQuery` и проверкой `initData`, это следующий шаг развития проекта.

## Меню и цены

Всё меню - в `webapp/menu.js`: категории, позиции, описания, опции (объём, выбор в комбо) и доплаты. **Цены примерные, перед запуском сверьте их** (там стоит `TODO`). Фото: `webapp/img/menu/<id>.webp`, 4:3.

Часы работы и шаг слотов самовывоза - там же, в `window.BAKERY`.

Цвета: фон, текст и подсказки берутся из темы Telegram (светлая/тёмная переключаются сами). Тёплый акцент задан в `style.css` переменной `--accent`; чтобы использовать цвет кнопок из темы Telegram, замените её на `var(--tg-theme-button-color)`.

## Локальная проверка мини-аппа

Откройте `webapp/index.html` в браузере (двойным кликом или через `python -m http.server` из папки `webapp`). Вне Telegram вместо системных кнопок появляется своя кнопка внизу, а "отправка" заказа печатает JSON в консоль браузера.

## Безопасность и ограничения концепта

- Токен и id админа только в переменных окружения, в коде их нет.
- Бот проверяет структуру заказа, длины строк и диапазоны чисел, экранирует текст и пересчитывает сумму по позициям. Битые данные не роняют бота: гость получает просьбу повторить, в лог пишется причина.
- Цены приходят из мини-аппа. Для настоящего сервиса бот должен сверять цены со своим справочником, а не доверять клиенту.
- Оплата не подключена: "оплата при получении".
